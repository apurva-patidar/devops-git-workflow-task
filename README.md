# DevOps Git Workflow Task 4

## Objective
To manage a DevOps project using Git and GitHub version-control best practices.

## Tools Used
- Git
- GitHub
- Ubuntu / WSL

## Project Activities
- Initialized a local Git repository.
- Created and managed Git branches.
- Practiced commits and pull requests.
- Used a `.gitignore` file.
- Created a Git tag for versioning.

## Branching Strategy
- `main`: Stable project version.
- `dev`: Development and integration branch.
- `feature/readme-update`: Feature development branch.

## Learning Outcomes
Learned Git commands, branch management, pull requests, versioning, and project documentation.

## Author
DevOps Intern
## Git Workflow Demonstration

This section demonstrates feature development using Git branches
and pull requests.

### Workflow Steps
1. Create a feature branch.
2. Make and commit changes.
3. Push the feature branch to GitHub.
4. Create a pull request into the dev branch.
5. Merge approved changes into dev.
6. Merge dev into main after verification.
